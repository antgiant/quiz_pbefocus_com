# PBE Quiz Builder

## Go-live checklist: shared header/footer site nav

`index.html`'s header/footer nav (`[data-pbe-site-nav]` /
`[data-pbe-site-footer-nav]`) is populated at runtime by
`https://pbefocus.com/site-nav.js`, shared across pbefocus.com, this app
(quiz.pbefocus.com), and karaoke.pbefocus.com (pbe-playlist) — see that
file's `SITES` array in the `pbefocus.com` repo. This app's `quiz` entry
there currently has `live: false`, so it only shows up in *this* site's own
nav (forced in via the current-site override) and stays hidden from
pbefocus.com's and karaoke's nav. **When this app actually goes live** (repo
pushed to GitHub, `quiz.pbefocus.com` DNS/CNAME live, GitHub Pages serving
it), flip `quiz`'s `live` to `true` in `pbefocus.com/site-nav.js` and
redeploy that repo — otherwise this app stays invisible from the other two
sites' navs indefinitely.

## Fill in the Blank

- `assets/js/blank-engine.js` is pure (no DOM, no storage): difficulty bands, TF-IDF, blank selection. Keep it that
  way so every output shares one result, and keep randomness seeded (`makeRng`).
- Generated questions carry `segments` (`{text}` / `{blank, word}`), `blankWords` and `generated: true`; renderers,
  print and PowerPoint read `segments` rather than re-deriving blanks.
- `compromise` is vendored at `assets/vendor/compromise.min.js` (license in `licenses/compromise/`).

## Testing

- Run `npm test` before committing; add or update tests in `tests/` with code changes.
- Tests load the vendored `compromise` file the same way the page does (see `tests/setup.js`).

## Data and loading

- `questions/v1/manifest.json`, `packs/` and the `practice-*.bundle.js` files are generated by `npm run build:data`
  (a GitHub Action does it on data pushes); never edit them by hand. `tests/build-data.test.js` fails when they are stale.
- Keep startup free of per-chapter requests and of blocking scripts; load heavy libraries through `assets/js/lazy-vendor.js`.
  Check changes that touch loading with `npm run bench` (see `docs/PERFORMANCE.md`).
